## Stage 1 — canonical four-view atlas (identity lock)
Generate four isolated full-body neutral model views in one image if possible: row 1 SE, SW; row 2 NE, NW. All views are the SAME character, same pose family, identical design, camera elevation and scale, consistent lighting. SE = front three-quarter facing screen right, SW = front three-quarter facing screen left, NE = rear three-quarter facing screen right, NW = rear three-quarter facing screen left. Head, shoulders, pelvis, feet and body plane must agree with direction; rear views show back of head/clothing and correct rear silhouette, not front face pasted onto back. No mirrored views; asymmetry is anatomically correct. Same ground plane and camera across all views; no perspective change or foreshortening from zoom. Neutral hands, no effects, no scenery/shadow/UI/text/watermark/borders. True alpha preferred. Flat unique chroma only if alpha backend unavailable; record and clean carefully without erasing clothes. Keep safe space around every cel, no overlaps. 
   
**Prompt skeleton (English, attach real images)**:
"Create a production reference atlas, not an illustration. Image A is the approved Naru STYLE reference only. Image B is the exact current character identity reference, if available. Image C is a layout guide only. Depict [ID, NAME, ERA, FORM] with [LOCKED DESIGN]. Four independently drawn full-body views of this one unchanged individual in neutral combat-ready stance: top-left SE (front-right), top-right SW (front-left), bottom-left NE (rear-right), bottom-right NW (rear-left). Identical head/body proportions, costume construction, palette and accessory anatomical sides. Consistent 3/4 camera and body scale. Neutral feet aligned, spacious isolated equal cells, transparent background. Preserve clean anime-chibi cel shading of A. No labels, effects, environment, visible guides, cropped limbs or copied/mirrored poses." 
   
Extract native PNGs model/se.png, sw.png, ne.png, nw.png, keep original atlas and hashes. Inspect four views together at native and runtime sizes. Check facial features, clothing across front/rear, emblem/prop placement and handedness. Reject discrepancies, correct only erroneous view using canonical master + correct views. Freeze entire model sheet hash and four directional hashes once approved. Do not change model midway; a deliberate model revision invalidates dependent clips and requires re-review.

## Stage 3 — deterministic processing
Keep originals (native unscaled PNGs), exact extraction regions, native isolated cels, model/clip metadata, source prompts and SHA. Validate actual file format, alpha, dimensions, full-body silhouette, cell count. Split by intended rows AND actual alpha bounds; connected components can be detached hair/prop, not automatically another cel. Fail ambiguous grouping, overlapping or clipped sprites; never use blind equal slicing. Use safe gutters and a row-aware region map. Do not independently resize every bbox to same height: this destroys natural crouch/strike/fall motion and moves feet. Determine one character scale from locked neutral anchors and preserve across all clips, ground root per pose; use contact foot/pelvis/root for airborne/fall rather than bbox bottom. Store offsets and scale. Separate high-res originals from 96x112 runtime derivative, anchor (48,104). Downsample once, choose filter appropriate to approved clean chibi art and inspect; no upscale disguised as high resolution. Repack exact horizontal runtime strip for each direction/action. Use path animation/NIN-xxx/action_dir.png and matching per-frame rect, duration_ms, anchor, sha256. Static path characters/NIN-xxx.png. Existing import_character_overlay expects 15 assets + 14 clip entries; do not modify engine contract just to accept invalid packs. Record extra portrait separately (not among 15). Forms require explicit form-specific binding and runtime verification; don't map form to base as if correct.
   
## Stage 4 — QA and corrective loop (fast but real)
Automate count, PNG RGBA, SHA, dimensions, alpha, nonempty, bounding box margins, distinct pixel hashes, expected action/direction coverage and metadata. For each clip inspect contact sheet at native + runtime size, then play actual GIF using metadata timing. Review loop seam for idle/move and one-shot endings for attack/cast/hit/fall. Compare character and each direction across action clips; verify visible face, haircut, proportions, palette, costume/prop side, same camera and correct direction. Use palette/silhouette/pose metrics as flags, not sole proof. Move R3 empirical ranges in RESEARCH.md; proposed warnings for per-clip height span >10px, center span >3px, bottom span >10px, neutral body scale drift >8%. These are review triggers, not reason to warp sprites; avoid applying move thresholds to falls/attacks. Hard rejection: wrong identity/era, inconsistent clothing, reversed anatomy, impossible limb, clipped cel, missing/duplicate frame, alpha halo, fake direction, baked effect. If only one row fails, rerender row from locked references; do not discard accepted siblings. Keep audit of attempts and failure reason. Limit blind retries: after two unsuccessful corrective attempts, simplify the layout, split row, or mark HOLD and report concrete blocker; never claim PASS.
